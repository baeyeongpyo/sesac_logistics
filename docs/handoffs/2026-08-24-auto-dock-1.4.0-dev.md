# Auto Dock 1.4.0-dev Handoff — 2026-08-24

## Scope

- `nav2/arrival` accepts the structured JSON contract while retaining legacy
  `arrived [left right]` input.
- Search uses lateral motion with heading correction instead of circular motion.
- Search stops only after a valid measurement and saves the odometry-based
  virtual target before stopping, so a later camera dropout does not restart
  search.
- A first matching frame schedules a stop after 0.2 seconds; the vehicle then
  remains stopped until the configured multi-frame confirmation succeeds.
- Final alignment uses lateral and yaw correction; insertion begins only after
  distance, center, and yaw tolerances all pass.
- A stable matching target with valid depth distance/yaw can use a depth-based
  fallback when close-range PnP reprojection quality is poor. Close targets
  between 10 cm and the normal standoff tolerance may still begin insertion.
- `auto_dock` publishes `UP`, `DOWN`, or `STOP` on `/fork/command`.
- The independent `fork_controller` publishes `UP_COMPLETE`, `DOWN_COMPLETE`,
  or `FAILED` JSON on `/robot_N/fork/state`.
- Both PICK and PLACE reverse, turn 180 degrees, and publish `drive_ready` after
  Fork completion.
- The active flow has no intermediate Nav2 `approach_goal/approach_result`;
  Auto Dock starts perception search directly from the successful arrival.
- The real-vehicle test panel can compose every arrival field and inject or
  observe Nav2/Fork completion events.

## Arrival contract

```json
{"status":"SUCCEEDED","location":"DOCK_1","operation":"PICK","product_type":"NORMAL","target":{"type":"SYMBOLS","left":"heart","right":"heart"}}
```

## Known development limitation

The in-node OpenCV detector finds the green 3x3 grid, warps it to a top view,
classifies each cell as FREE/OCCUPIED/UNKNOWN, and applies the deep-first slot
priority after three confirming frames. A clipped or ambiguous grid remains
UNKNOWN. Explicit `SLOT` values such as `R2C1` are normalized and recorded.
Slot-to-pose travel and final placement are not implemented yet, so neither
`SLOT` nor `AUTO_SLOT` may be described as physically operational.

## Vehicle 2 launch integration

The vehicle-2 source at
`/home/ubuntu/ros2_ws/src/navigation/launch/navigation.launch.py` now starts
the independent `fork_control/fork_controller` node. The matching navigation
`package.xml` declares `fork_control` as an execution dependency. Restart the
team's navigation launch to load this change; the already-running launch is not
restarted automatically during deployment.

Insertion distance and speed are controlled in
`/shared/vehicle_pose_config.json`:

```json
{"insertion_distance_cm": 15, "insertion_speed_m_s": 0.08}
```

Post-fork manoeuvre values use the same JSON keys:

```json
{"post_lift_reverse_distance_cm": 30, "post_lift_reverse_speed_m_s": 0.05,
 "post_lift_turn_deg": 180}
```

Because standard JSON does not support comments, the deployed shared config
places ignored `_comment_<setting>` string fields immediately before each
Auto Dock setting. Obsolete Nav2 approach settings were removed.
