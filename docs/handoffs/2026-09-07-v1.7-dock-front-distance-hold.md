# v1.7 optional DOCK lateral front-distance hold

User requested only a small removable addition to v1.7 to compensate longitudinal drift during DOCK PICK lateral motion. Added auto_dock/dock_front_distance_hold.py, with one import, one publish_drive hook and one new-mission reset in auto_dock_node.py. No changes to selection, yaw, Y placement, launcher, GUI or runtime config files.

The median positive finite forward distance of currently front-facing symbol tags (bearing within ±20 degrees, detection receipt age at most 0.8s) becomes the reference at lateral start. A 2cm absolute error starts a pure ±0.10m/s longitudinal correction; within 1cm it resumes lateral motion. Axes are separated to avoid mixed wheel components falling into the vehicle dead zone. Stops pass through; deliberate non-lateral translation or rotation resets the reference. Missing/stale front-tag data passes through the original command, rather than inventing a distance. Tag faces at different depths or changing visible rows can affect the median; physical holding accuracy is not yet verified.

Disable by setting dock_lateral_front_hold_enabled=false in /shared/vehicle_pose_config.json. Removal: delete the import, publish_drive call and mission-reset line, then remove dock_front_distance_hold.py and normal-build auto_dock. This is separate from the superseded pre-rollback changes.

Local offline suite: 353 passed. Vehicle deployment/test/build/hash evidence: analysis/dock_front_hold_20260907. Runtime/launch/vehicle execution is user-only; agent did not start, stop or restart anything.
