# ARANEUM 발표자용 질의응답 메모

본문 20분에 추가로 읽는 분량이 아니다. 확인한 범위로 답하고, 실제 고객·성능 검증을 수행한 것처럼 말하지 않는다.

**이미 AMR이 있는데 왜 필요한가요?**

“자동 운반 장비는 이미 시장에 있습니다. 저희가 사업화하려는 부분은 고객 현장의 반복 이송 구간을 먼저 검토하고, 적합한 장비와 작업·재고 관리를 연결하는 도입 과정입니다. 기존 제품보다 얼마나 효과적인지는 실제 파일럿에서 비교해야 합니다.”

**어떤 지게차든 소프트웨어만 설치하면 되나요?**

“적용할 장비의 제어 방식과 센서, 운행 조건을 확인해야 합니다. 오늘 보여드리는 것은 MentorPi M1 기반 소형 실증입니다. 실제 지게차 활용은 적용 가능성을 검토하고 별도 장비 시험을 거쳐야 합니다.”

**정확히 무엇을 판매하려는 건가요?**

“우선 반복되는 한 이송 구간의 현장 검토와 파일럿을 제안하고, 결과에 따라 장비 연동과 작업·재고 관제 구축, 운영 지원으로 이어가는 방식을 생각하고 있습니다. 아직 검증할 사업 모델입니다.”

**시뮬레이션에서 잘 되면 현장에서도 잘 되나요?**

“가상 환경은 배치와 작업 흐름을 비교하는 데 사용합니다. 실제 바닥·센서·하역 조건이 다르기 때문에 실차 결과와 비교해 확인해야 합니다. 현재 원고에는 처리량 예측 정확성이나 필요한 차량 수를 확정한 결과를 넣지 않았습니다.”

**얼마나 빨라지고 비용이 얼마나 줄어드나요?**

“현재 제시할 수 있는 반복 측정 수치는 없습니다. 파일럿에서 기존 방식과 같은 조건으로 작업 시간, 개입 횟수, 성공률을 비교하고, 장비·연동·운영 비용까지 함께 평가하려 합니다.”

**팔레트마다 고유 번호가 없어도 되나요?**

“현재 실증에서는 종류와 구역별 수량, 차량의 적재 상태와 운반 작업을 관리합니다. 개별 팔레트 추적이 필요한 현장에서는 바코드나 RFID 식별과 그에 맞는 데이터·업무 연동을 추가해야 합니다.”

**대기 구역의 물건은 공간만 생기면 바로 옮기나요?**

“현재 규칙은 입고 위치의 물류를 먼저 처리하고, 그곳이 비었을 때 대기 구역에서 작업 구역을 보충합니다. 먼저 처리할 물류가 일반 물류보다 우선합니다. 공간뿐 아니라 이 작업 순서도 확인합니다.”

**정지와 취소는 어떻게 다른가요?**

“정지는 움직임에 개입하는 기능이고, 취소는 지정한 활성 주행 작업을 취소하는 요청입니다. 현재 구현에서는 둘 다 관련 주행을 중단하고, 다음 작업 전에 운영자 확인이 필요합니다. 정지하면 기존 작업을 그대로 자동 재개한다거나 취소하면 재고가 자동으로 되돌아간다고 설명하지 않습니다.”

**SLAM과 Nav2의 차이는 무엇인가요?**

“SLAM은 센서로 지도를 만들며 위치를 추정하는 기술입니다. 저장된 지도를 사용하는 주행에서는 현재 센서 관측과 지도를 비교해 위치를 추정하고, Nav2가 목적지로 이동하기 위한 경로와 주행을 처리합니다.”

**Open-RMF나 YOLO·Depth는 어디에 쓰이나요?**

“Open-RMF는 여러 로봇의 작업과 공유 공간의 이동 일정을 연계하는 쪽이고, 개별 차량의 주행과 포크 제어는 차량 측 기능과 연결해야 합니다. 영상 객체 검출과 거리 정보는 팔레트를 찾고 가까이 정렬하는 데 사용할 수 있습니다.”

발표자 주의: 마지막 답변은 기술의 역할 설명이다. 프로젝트의 Open-RMF 두 차량 운용과 YOLO·Depth Auto Dock 검증 단계는 사용자 확인을 받기 전까지 별도 메모로 유지한다. 실차 검증, 시뮬레이션 검증, 기능 구현만 한 상태를 구분해 답한다.
