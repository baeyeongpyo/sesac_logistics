# 1회차 기술 관점 검토

핵심 판단: 기존 대본은 실차 범위와 완료 확인이 정확하지만 기능 역할이 추상적이다. 새 원고는 운전자의 일을 나눠 설명해 이해하기 쉽지만, 기술명 반복과 산업용 지게차 개조 완료로 읽히는 결론이 약점이다. 기존의 시연·검증 경계에 새 원고의 역할 설명을 통합한다.

1. 새 원고의 “SLAM은 나는 어디 있는가”는 지도 생성과 운행 중 위치추정을 섞는다. 선택 위키의 주행 스택 §2는 SLAM 지도 생성과 저장 지도·AMCL 주행을 구분한다. 청중에게 AMCL까지 외우게 하기보다 ‘미리 만든 지도에서 현재 위치를 찾는다’고 설명한다.
2. “Open-RMF가 … 로버와 경로를 배정”은 Nav2와 같은 운전 기능으로 들린다. 관제의 작업·이동 순서 조정, 차량의 주행, 팔레트 앞 근거리 정렬을 나눈다. Nav2 접근 뒤 Auto Dock으로 넘기는 구분은 유지하되, YOLO·Depth로 자세까지 추정한다는 설명은 사용자 주장이다. [공식 Fleet Adapter 설명](https://osrf.github.io/ros2multirobotbook/integration_fleets_adapter_tutorial.html)은 관제 명령을 차량 API로 전달하는 역할을 뒷받침할 뿐 프로젝트 연동 완료의 증거는 아니다.
3. 마지막 “사람이 운전하던 지게차를 … 자율화”와 “몇 대가 필요한지 … 미리 검증”은 현재 시연보다 넓다. 기존 대본의 소형 MentorPi M1 검증 범위를 유지한다. Open-RMF·포화 대기·YOLO/Depth 구현은 사용자 제공 정보, P3 완료 이벤트 연계는 문서 확인, 실차 성공은 별도 시험으로 구분한다. 코드 미확인을 미구현으로 단정하지 않는다. Gazebo 사전 검토만으로 실시간 동기화나 처리량 예측 정확성을 주장할 수 없다.

교체 문장:

- “미리 지도를 만들고, 운행할 때는 센서와 저장된 지도를 비교해 현재 위치를 찾습니다.”
- “관제는 작업과 이동 순서를 조정하고, 차량은 목적지까지 주행한 뒤 팔레트 앞에서 정렬과 적재를 수행합니다.”
- “오늘은 소형 실차로 이송·하역·재고 연결을 보여드리며, 기존 지게차 적용과 현장 처리량 예측은 추가 검증할 확장 목표입니다.”

판단: 재수정. 역할 설명은 살리고, 구현 주장과 시연 범위의 경계를 본문에서 바로 들리게 해야 한다.
