# ARANEUM 현장 발표 대본 — 통합 초안 v1

전체 20분 목표. PPT 없이 실제 공간과 차량·로봇암·관제 화면을 사용한다. 대괄호는 낭독하지 않는 행동 지시다. 시간은 관찰·화면 전환을 포함한 진행 기준이며 리허설 실측값이 아니다. 시연의 완료 멘트는 실제 동작과 상태를 확인한 뒤 읽는다.

## 00:00–02:00 — 운영자의 하루에서 시작

[팔레트 실물과 입고 위치를 가리킨다.]

안녕하세요. 물류 자동화 프로젝트 ARANEUM을 소개하겠습니다.

먼저 여러분이 이 물류센터의 운영자라고 생각해 보겠습니다. 매일 트럭이 들어오고, 물건을 실은 팔레트가 도착합니다. 여기 보이는 물건 받침대가 팔레트입니다. 여러 물건을 한 번에 옮길 수 있도록 받쳐주는 운반 단위입니다.

들어온 물건을 입구에 계속 쌓아둘 수는 없습니다. 누군가는 무엇을 먼저 처리할지 확인하고, 지게차로 팔레트를 들어서 다음 작업 장소로 옮겨야 합니다. 내려놓은 뒤에는 다시 돌아와 다음 팔레트를 가져옵니다.

그런데 운영자가 신경 써야 하는 것은 이동 시간만이 아닙니다. 목적지에 자리가 있는지, 다음 작업을 시작해도 되는지, 실제 물건 위치와 기록이 맞는지도 확인해야 합니다. 장비가 움직여도 이 인계가 늦어지면 다음 공정은 기다리게 됩니다.

[입고 위치에서 P3까지 손으로 경로를 안내한다.]

저희는 이 반복적인 운반과 인계를 자동화하고 싶었습니다. 기존 현장의 작업 흐름을 가상 공간에서 먼저 검토하고, 차량의 운반과 작업·재고 관리를 연결하는 것이 ARANEUM의 방향입니다.

오늘 앞에 있는 공간은 이를 시험하기 위해 만든 소형 실증 환경입니다. 실제 물류센터의 입고와 이송 구조를 참고했습니다. 이곳에서 어떤 판단을 자동화했는지 설명드리고, 차량과 로봇암을 약 5분 동안 직접 움직여 보여드리겠습니다.

## 02:00–04:00 — 무엇을 먼저, 어디로 옮길 것인가

[입고 위치, P3, 물류 대기 구역을 차례로 가리킨다.]

공간부터 짧게 소개하겠습니다. 이쪽 도크는 들어온 물류를 인수하는 출발지이고, 저쪽 P3는 오늘 팔레트를 내려놓을 목적지입니다. 대기 구역은 물건을 임시로 놓는 장소입니다.

시연 공간에서는 물류를 먼저 처리해야 하는 종류와 일반적인 종류로 나눴습니다. 처리 순서를 단순하게 정해 자동화 흐름을 확인하기 위해서입니다. P3는 목적지의 이름입니다.

팔레트가 들어오면 시스템은 종류와 목적지의 남은 공간을 확인합니다. 옮길 수 있으면 운반 작업을 만들고, 작업 가능한 차량에 연결합니다. 운영자가 매번 차량의 방향을 조작하기보다, 어떤 물류를 어느 곳으로 옮길지 작업으로 관리하는 방식입니다.

예를 들어 목적지에 물건이 가득 찼다고 해보겠습니다. 계속 같은 곳으로 보내면 물건을 내려놓을 수 없습니다. 저희는 이런 경우 종류에 맞는 대기 구역으로 먼저 옮기는 규칙을 두었습니다.

대기 구역의 물류는 목적지의 공간과 입고 대기 물류의 처리 순서를 확인해 다시 옮깁니다. 현재 규칙에서는 입고 위치의 물류를 먼저 처리한 뒤 대기 구역의 물류를 목적지로 보충합니다.

이 과정에서 물건의 종류와 구역별 수량, 운반 작업의 결과를 함께 관리합니다. 차량이 가져갔는지, 어디에 내려놓았는지 알아야 다음 물류를 처리할 수 있기 때문입니다.

이렇게 반복 이송, 목적지 선택, 공간 확인, 완료 기록을 하나의 흐름으로 묶었습니다. 오늘 시연에서는 그중 도크에서 P3까지 팔레트를 옮기는 작업을 따라가겠습니다.

## 04:00–07:00 — 실제 설치 전에 가상 환경에서 확인

[실제 통로와 작업 위치를 가리킨다. Gazebo 화면이 준비되어 있으면 같은 공간을 짧게 대응시킨다.]

이 흐름을 실제 현장에 적용하려면 먼저 확인해야 할 것이 있습니다. 우리 통로에서 차량이 이동할 수 있는지, 팔레트를 받는 위치가 적절한지, 작업이 어느 순서로 진행되어야 하는지입니다.

장비를 설치한 뒤에야 동선의 문제가 드러나면 배치를 바꾸고 작업을 다시 맞춰야 합니다. 그래서 저희는 Gazebo라는 시뮬레이터에 가상 물류 환경을 구성해 먼저 확인했습니다.

벽과 통로, 출발지와 목적지, 차량을 컴퓨터 안에 배치하고 운반 작업을 실행해 보는 것입니다. 같은 조건에서 반복할 수도 있고, 목적지나 이동 경로를 바꿔볼 수도 있습니다. 실물에서 조정하기 전에 동작과 작업 순서를 확인하는 데 활용했습니다.

그 이후 지금 보시는 실제 공간과 MentorPi M1 차량으로 옮겼습니다. 이 차량은 소형 실증용 장비입니다. 실제 산업용 지게차에 적용하는 단계에서는 장비의 제어 방식과 센서, 하중과 현장 조건을 별도로 검토해야 합니다.

가상 환경과 실제 공간 사이에도 차이가 있습니다. 실제 바닥에서 차량이 움직이는 모습, 센서가 읽는 값, 팔레트에 접근하는 자세가 작업에 영향을 줍니다. 그래서 가상 검증 뒤에 실차로 이동과 인계 결과를 다시 확인하는 과정을 두었습니다.

사업화할 때도 이 순서를 활용하려 합니다. 고객 현장의 특정 이송 구간을 먼저 살펴보고, 가상 환경에서 배치와 작업 흐름을 비교한 뒤, 실제 장비로 시험하는 방식입니다. 전체 현장을 한꺼번에 바꾸기보다 반복되는 한 구간부터 적용 가능성을 확인할 수 있습니다.

이를 디지털 트윈 기반 사전 검증으로 확장하려는 방향도 있습니다. 예를 들어 차량 수나 대기 위치를 바꾸었을 때 작업 흐름이 어떻게 달라지는지 비교할 수 있습니다. 다만 가상 결과가 실제 처리량과 얼마나 맞는지는 현장에서 측정하며 확인해야 합니다.

현재 프로젝트에서는 가상 환경에서 검토한 흐름을 소형 실차 환경으로 옮기는 기반을 구성했습니다. 앞으로 실측 결과를 쌓으면, 장비나 배치를 결정할 때 제공하는 근거도 더 구체적으로 만들 수 있습니다.

## 07:00–10:00 — 사람이 하던 판단을 어떻게 나누었는가

[차량의 센서, 포크, 관제 화면을 차례로 가리킨다.]

이제 차량이 스스로 작업하기 위해 필요한 역할을 설명드리겠습니다. 크게 위치를 파악하는 일, 이동하고 팔레트를 취급하는 일, 전체 작업을 관리하는 일로 나눌 수 있습니다.

사람이 지게차를 운전할 때는 통로의 구조와 자신의 위치를 압니다. 차량도 같은 정보가 필요합니다. 센서로 주변 지도를 만들고, 주행할 때는 지도와 현재 관측을 비교해 자신의 위치를 파악합니다. 지도 생성에는 SLAM이라는 기술을 사용합니다.

위치를 파악했으면 목적지까지 이동해야 합니다. 이 역할에 Nav2를 사용했습니다. 지도와 현재 위치, 목적지를 바탕으로 이동 경로를 계산하고 차량이 그 경로를 따라 움직이도록 합니다.

팔레트를 집기 위해서는 마지막 정렬 과정도 필요합니다. 사람도 팔레트 앞에서 조금씩 움직이며 포크를 맞춥니다. 저희는 목적지 근처까지 가는 주행과, 팔레트를 집기 위한 가까운 거리의 정렬을 나눴습니다. 이 마지막 접근과 정렬을 담당하는 과정이 Auto Dock입니다.

적재와 하역의 결과는 관제에 전달합니다. 명령을 보냈다는 사실과 실제 동작을 마쳤다는 결과를 구분해서 다음 단계를 진행합니다. 팔레트를 가져왔으면 출발지의 수량과 차량의 적재 상태를 바꾸고, 내려놓았으면 목적지의 수량과 작업 완료 상태를 반영합니다.

[관제 화면의 위치·작업 상태·재고 표시를 짚는다.]

이 화면은 운영자가 전체 진행 상황을 확인하는 곳입니다. 차량이 어디에 있고, 어떤 작업을 수행하는지, 물류 데이터가 어떻게 바뀌었는지 확인할 수 있습니다.

여러 차량을 운영할 때는 작업을 나눠주고 공용 공간의 이동 순서를 조정하는 역할도 필요합니다. Open-RMF는 여러 로봇 그룹의 작업과 이동 일정을 연계하는 데 사용하는 프레임워크입니다. 차량이 목적지까지 실제로 움직이는 역할과, 전체 작업을 조정하는 역할은 나눠서 봐주시면 됩니다.

저희가 확인한 현재 구조에서는 물류 작업을 판단하는 부분과 차량 모델별 통신·제어 부분을 분리해 연결했습니다. 같은 작업이라도 차량마다 명령을 받는 방식이 다를 수 있기 때문입니다. 다른 차종을 추가할 때는 해당 장비의 연동 부분과 지원 기능을 맞춰야 합니다.

운영자는 이 화면에서 필요할 때 원격으로 정지와 작업 취소를 요청할 수 있습니다. 중단 이후에는 차량과 화물 상태를 확인하고 다음 작업을 허용하도록 구성했습니다. 정상 작업을 자동으로 진행하는 것과 운영자가 예외 상황에 개입하는 것을 함께 고려했습니다.

지금부터 차량의 움직임과 화면을 함께 보면서 이 과정을 확인하겠습니다.

## 10:00–15:00 — 차량·로봇암 시연

### 시연 00:00–02:00 — 차량 이동과 로봇암 동시 동작

[P3 작업과 로봇암을 시작한다. 차량·작업 상태와 재고 화면을 함께 보이게 둔다. 먼저 차량, 다음 로봇암, 다음 관제 화면 순서로 안내한다.]

지금부터 팔레트를 P3로 옮기는 작업을 시작하겠습니다. 차량이 이동하는 동안 로봇암도 함께 동작합니다. 먼저 차량을 보시고, 이어서 로봇암과 화면을 안내해 드리겠습니다.

[차량 출발 확인 후.]

차량이 지정된 작업에 따라 이동하고 있습니다. 목적지를 주고 나면 차량이 주행을 수행합니다. 도착 후에는 팔레트를 내려놓는 동작과 작업 결과를 확인하겠습니다.

[로봇암 동작 확인 후.]

이쪽 로봇암도 움직이고 있습니다. 차량은 물류를 운반하고, 로봇암은 작업 구역에서 필요한 동작을 맡습니다. 오늘은 두 장치의 동작을 동시에 보여드리고 있습니다. 차량이 가져온 이번 팔레트의 분류까지 연속 실행하는지는 오늘 보여주는 범위와 구분해서 봐주시면 됩니다.

[관제 위치 표시를 가리킨다.]

여기서는 차량의 현재 위치와 작업 상태를 확인할 수 있습니다. 실제 차량과 화면을 함께 보시면 작업이 어느 단계에 있는지 파악할 수 있습니다.

[차량과 로봇암 동작을 관찰할 시간을 준다. 차량 이동 약 2분은 사용자의 예상이며 실제 도착에 맞춰 진행한다.]

### 시연 02:00–04:30 — 하역·데이터 확인과 정지·취소

[P3 도착 후.]

차량이 P3에 도착했습니다. 이제 팔레트를 내려놓는 모습과 물류 데이터의 변화를 함께 확인하겠습니다. 물건을 목적지에 실제로 내려놓아야 인계가 끝난 것입니다.

[하역 완료와 데이터 반영을 확인한 뒤.]

지금 하역을 마쳤고, P3의 재고와 작업 완료 상태에 결과가 반영되었습니다. 차량의 적재 상태도 함께 확인할 수 있습니다. 이렇게 실제 동작의 결과를 다음 작업의 판단에 사용할 수 있도록 연결했습니다.

[완료한 P3 재고 화면은 유지한다. 복귀 또는 준비한 별도 짧은 주행 중 정지를 요청한다.]

팔레트 인계를 마쳤으니, 이제 이후 주행 작업에서 원격 정지와 취소를 보여드리겠습니다. 먼저 이동 중인 차량에 정지를 요청하겠습니다.

[차량 정지와 상태 표시 확인 후.]

차량이 멈췄고, 화면에서도 변경된 상태를 확인할 수 있습니다.

[운영자가 상태를 확인하고 다음 작업을 허용한다. 별도 주행 작업을 시작한 뒤 해당 활성 작업에 취소를 요청한다.]

차량 상태를 확인한 뒤 별도 주행을 시작했습니다. 이번에는 이 주행 작업에 취소를 요청하겠습니다.

[취소 결과 확인 후.]

주행 작업의 취소가 반영되었습니다. 중단 이후에는 운영자가 상태를 확인한 뒤 다음 작업을 허용합니다. 앞서 완료한 팔레트 인계 결과는 재고 화면에서 함께 확인할 수 있습니다.

### 시연 04:30–05:00 — 결과 연결

[작업 완료와 재고 화면을 가리킨다.]

지금까지 팔레트 이송과 하역, 로봇암의 동작, 물류 데이터 반영, 원격 정지와 취소를 보셨습니다. 실제 운반 결과와 운영자의 확인·개입을 하나의 작업 흐름으로 연결한 모습입니다.

## 15:00–18:00 — 고객이 구매할 수 있는 것은 무엇인가

[전체 공간을 가리킨다.]

사업 관점에서 저희가 먼저 생각하는 고객은 반복적인 팔레트 이송과 인계 확인에 부담을 겪는 물류센터 운영사입니다. 기존 공간에서 어느 구간을 자동화할지 판단하고 싶은 고객을 대상으로 합니다.

자동 운반 로봇과 지게차 기반 자동화는 이미 시장에 있습니다. 고객 현장에 맞는 장비를 선택하고, 물류 규칙과 작업 완료·재고 관리를 실제 운영에 연결하는 과정이 필요합니다. ARANEUM은 그 도입과 운영 과정을 이어주는 서비스를 지향합니다.

출발점에는 사람이 사용하던 지게차의 운반 업무를 자율화할 수 있을까라는 질문이 있었습니다. 기존 장비를 활용할 수 있다면 그 가능성을 먼저 검토하고, 현장과 장비 조건에 따라 상용 자동 운반 장비를 연동하는 선택지도 함께 볼 수 있습니다.

오늘 보여드린 것은 소형 장비에서의 실증입니다. 실제 지게차의 개조나 현장 설치는 적용할 장비와 운행 조건을 검토하고 추가로 검증해야 하는 단계입니다.

고객에게 처음 제안할 수 있는 단위는 특정 이송 구간의 현장 검토와 파일럿입니다. 어디서 물건이 들어오고 어디로 가는지, 어느 단계에서 기다리는지 확인한 뒤 가상 환경에서 배치와 작업 흐름을 비교합니다. 이후 실제 장비로 시험해 적용 가능한 범위를 정하는 방식입니다.

이때 고객이 받는 결과는 적용할 이송 구간과 장비 연동 조건, 가상 검토 결과, 그리고 실차 시험에서 확인한 작업 시간과 개입 지점입니다. 이를 보고 실제 구축을 진행할지 판단할 수 있도록 하려 합니다.

수익 모델은 현장 검토와 파일럿에 대한 비용, 이후 시스템 구축과 운영 지원 비용으로 이어가는 방향을 생각하고 있습니다. 아직 고객 검증이 필요한 사업 가설이며, 실제 가격이나 절감 효과가 확정된 단계는 아닙니다.

사업성을 확인할 때는 같은 이송 작업을 기준으로 작업 시간과 수동 개입 횟수, 성공률을 비교하려 합니다. 장비와 연동, 운영에 필요한 비용도 함께 봐야 합니다. 고객이 줄이고 싶은 대기와 확인 부담을 실제로 얼마나 줄일 수 있는지가 판단 기준입니다.

반복되는 한 구간에서 이런 결과를 확인한 뒤, 인접한 공정과 차량으로 적용 범위를 넓혀가는 방식을 목표로 하고 있습니다.
