# ARANEUM 병렬 검토 공통 지시

사용자가 기존 대본과 새 원고를 3개 관점의 서로 다른 에이전트가 병렬 검토하고, 수정본을 총 5회 반복 검증하여 비교분석과 최종 대본으로 정리하라고 명시적으로 요청했다. 한국어로 작성한다.

## 입력과 산출물

- 기존 대본: `docs/presentation-live-demo-script-2026-09-06.md` (읽기 전용으로 보존)
- 새 사용자 원고: `docs/araneum-review/source-new-user-script.md`
- 프로젝트 지식: `.agent-harness/bundles/run-20260905-203106/`의 4개 필수 파일과 선택 페이지를 먼저 확인한다. 이미 읽은 지침은 반복해서 읽지 않아도 된다.
- 최종 조건: 전체 20분, PPT 없음, 현장에서 장치와 관제 화면을 보며 발표. 시연 약 5분, 차량 이동 약 2분과 로봇암 동시 동작, P3 도착 후 데이터·정지·취소 시연을 함께 진행.
- 코디네이터가 현재 대본의 사실 주장, 시간, 3개 관점을 통합한다. 리뷰어는 자신의 보고서 파일만 작성하고 공유 대본·프로젝트 코드·위키는 수정하지 않는다.
- 소형 MentorPi M1 시연을 산업용 지게차 개조 완료로 표현하지 않는다. Open-RMF·YOLO/Depth·포화 대기 구역 기능은 새 사용자 원고가 주장하지만 이 작업 공간의 직접 근거가 충분하지 않을 수 있다. 사용자 제공 설명과 코드 확인과 실차 시험을 구분하고, 코드 부재를 미구현 증거로 단정하지 않는다.
- 가상 환경 사전 검증과 실시간 동기화/처리량 예측 정확성이 검증된 디지털 트윈을 구분한다. 성능/원가/ROI 수치는 새로 만들지 않는다.

## 5회 반복 프로토콜

각 리뷰어는 하나의 활성 Orca Dispatch 안에서 1~5회를 진행한다. 1회는 두 입력의 비교분석이며, 2~5회는 코디네이터가 두 대본을 통합·수정한 공통 초안의 재검토다. 매 회 결과를 파일에 남기고 코디네이터가 다음 버전을 전달할 때까지 Orca 구조화 메시지를 기다린다. 5회가 끝나기 전에 worker_done을 보내거나 최종 종료하지 않는다.

1. 원고 비교: 기존/새 원고의 장점·약점, 관점별 가장 큰 오해, 통합 방향.
2. 이해와 메시지: `draft-v1.md`를 검토한다. 한 번 듣고 재설명할 수 있는가.
3. 반론과 표현: `draft-v2.md`를 검토한다. 과장, 기술 역할 혼동, 구매 이유의 빈틈을 찾는다.
4. 현장 낭독: `draft-v3.md`를 검토한다. 장치 주목 순서, 동시 시연, 시간, 자연스러운 말투를 본다.
5. 최종 승인: `draft-v4.md`를 검토한다. 남은 치명적 문제와 최소 수정, 20분 현장 원고로서의 최종 판단을 기록한다.

보고서 경로는 `docs/araneum-review/round-N-ROLE.md`. ROLE은 audience, technical, business 중 자신의 역할이다.

각 보고서는 600~1000 한국어 글자 정도로 간결하게: (1) 핵심 판단, (2) 구체적인 문장/위치에 근거한 가장 중요한 3개 지적, (3) 바로 쓸 교체 문장 최대 3개, (4) 수용/조건부 수용/재수정 판단. 1회만 두 원고를 직접 비교한다. 실제 사람 실험을 한 것처럼 표현하거나 근거 없는 점수/합격률을 만들지 않는다. 이전 회차의 지적이 해결됐는지 다음 회차에서 확인한다.

각 회차 보고서를 저장한 뒤 `orca orchestration send --type status --subject 'ROLE round N ready' --body '파일 경로 및 핵심 결론' --json`으로 코디네이터에게 알린다. 이후 `orca orchestration check --wait --timeout-ms 60000 --json` 등 현재 guide에 맞는 구조화 check로 다음 회차 메시지를 기다린다. 대기 시간이 끝났다는 이유로 임의의 다음 버전을 상상하거나 회차를 혼자 진행하지 않는다. 매 회차에는 실제 다른 수정본을 읽는다.

5회 최종 보고 후 주입된 task/dispatch ID를 사용해 정확히 한 번 worker_done을 보내고 종료한다. 다른 에이전트 추가 생성은 하지 않는다. 사실 확인은 필요한 범위에만 한정하고 대본 검토가 아닌 제품 개발로 범위를 넓히지 않는다.
