# 3회차 기술 관점 검토

검토 대상: draft-v2.md.

핵심 판단: 2회차에서 지적한 도크 정렬·적재→P3 이동→하역 순서가 정확해졌다. 로봇암도 각자 동작을 보여주는 범위로 정리됐다. 산업용 개조 완료와 처리량 보장 주장이 없고, 기술명보다 기능 설명이 앞선다. 남은 문제는 근거 미확인을 미래 기능처럼 돌리는 표현과 시연 시간의 범위다.

1. 07:00–10:00의 “이동 일정까지 조정하는 것은 관제를 확장할 때 … 다뤄야”는 사용자 원고가 주장한 Open-RMF 두 차량 운용을 아직 구현하지 않았다고 들릴 수 있다. 적용 단계가 답변 대기라면 현재·미래를 확정하지 않고 ‘여러 차량 운영에 필요한 역할’로 설명한다. 역할 분리는 유지하되 코드 확인 부재를 구현 부재로 바꾸지 않는다.
2. 02:00–04:00의 “시스템은 종류와 목적지의 남은 공간을 확인”은 카메라가 종류와 빈자리를 모두 직접 판별하는지 질문을 부른다. 확인한 관제 근거는 종류·재고·예약 정보로 목적지를 정하는 로직이다. 입력을 읽는 판단과 영상 인식을 구별하고, YOLO·Depth 본체 확인 전에는 인식 방식이나 정렬 정확도까지 확대하지 않는다. 등록 정보라는 설명은 별도 인식 기능의 존재를 부정하지 않는다.
3. 시연 첫 2분에 도크 접근·정렬·적재와 P3 이동을 모두 넣었지만, 사용자 시간 조건은 ‘차량 이동 약 2분’이다. 기술 순서를 바로잡으면서 앞단 동작 시간이 추가됐으므로 전체 작업이 2분이라고 단정할 수 없다. P3 도착이 늦어도 완료 멘트를 먼저 읽지 않도록 행동 기준과 5분 운영안을 맞춰야 한다.

교체 문장:

- “여러 차량이 함께 움직일 때 관제는 작업과 이동 일정을 조정하고, 각 차량은 실제 주행을 수행합니다.”
- “관제는 등록된 물류 종류와 구역별 재고, 이미 보내기로 한 물류를 함께 보고 목적지를 정합니다.”
- “[도크 접근·적재 시간을 주행 약 2분과 구분해 리허설에서 측정하고, 실제 P3 도착에 맞춰 다음 설명으로 넘어간다.]”

판단: 조건부 수용. 기술 역할의 큰 혼동은 해소됐으며, 미확인 기능의 시제와 시연 시간 범위를 조정하면 된다.
