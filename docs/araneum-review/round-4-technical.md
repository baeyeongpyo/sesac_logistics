# 4회차 기술 관점 검토

검토 대상: draft-v3.md. 실제 낭독·실차 시험은 하지 않았다.

핵심 판단: 등록 정보에 따른 관제 판단과 영상 인식을 분리했고, Open-RMF 미확인을 미구현으로 바꾸는 시제도 없어졌다. 주행 약 2분과 적재·하역 시간을 구분하고 실제 이벤트로 멘트를 전환해 3회차 지적이 해결됐다. 현장용으로는 반복 설명과 정지 시연 대상 선택이 남는다.

1. 07:00–10:00은 행동 지시를 뺀 낭독 후보가 1,252자로, 앞선 가상 환경 구간 992자보다 길면서 센서·포크·화면을 연속 가리킨다. 이미 02:00–04:00에서 관제를 정의했는데 다시 두 문단으로 설명한다. 정의를 줄여 각 장치를 바라볼 틈을 확보한다. 글자 수는 실제 발표 시간 측정값이 아니다.
2. 시연의 “[도크 접근·정렬·적재 중 실제 단계에 맞춰]” 뒤 한 문장은 “포크를 맞추고 있습니다”로 고정돼 있다. 접근 중 또는 이미 적재 중이면 관찰과 발화가 어긋난다. 포크 정렬 멘트의 시작 조건을 정렬 동작 확인으로 좁히고, 이동·적재 완료는 각각 확인된 단계에서 말한다.
3. 정지 대상이 여전히 “복귀 또는 … 별도 짧은 주행”이다. Orchestrator README의 복구 절에 따르면 P3 복귀 중 중단은 완료된 재고와 별개로 FAILED workflow를 남길 수 있다. 당일 선택지로 두면 화면 설명과 다음 작업 시작이 달라진다. 정상 복귀 종료 후 준비된 짧은 주행 둘에 정지와 취소를 각각 적용하는 흐름을 우선 정하고, 복귀까지 포함해 5분 가능 여부를 리허설에서 확인한다.

교체 문장:

- “관제는 다음 작업을 정하고, 이 화면은 차량의 위치와 작업·재고 결과를 보여줍니다.”
- “[포크 정렬 동작을 확인한 뒤] 지금 팔레트에 포크를 맞추고 있습니다.”
- “[P3 복귀 종료와 비적재 상태 확인 후 짧은 주행 A에서 정지, 운영자 확인 후 별도 주행 B에서 취소를 시연한다.]”

판단: 조건부 수용. 기술 정확성의 치명적 문제는 없으나, 정지 대상과 상태 전환을 하나로 정해야 현장 진행을 재현할 수 있다.
