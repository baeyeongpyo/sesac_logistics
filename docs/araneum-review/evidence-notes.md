# ARANEUM 원고 사실·표현 근거

확인일 2026-09-06. 이 문서는 발표 표현을 검토하기 위한 로컬 기록이며, 실제 차량을 운행하거나 새 성능 실험을 한 증빙이 아니다. 코드를 변경하지 않고 현재 작업 트리의 문서/소스를 확인했다. 사용자 제공 원고의 주장은 별도 프로젝트 구성에서 구현되었을 수 있으므로 이 저장소의 검색 부재를 미구현 증거로 취급하지 않는다.

| 원고 주장 | 확인된 내용 | 발표 처리 |
| --- | --- | --- |
| 먼저 처리할 팔레트와 일반 팔레트 | Orchestrator README의 FRESH 우선/NORMAL 후순위 규칙, service.py 작업 선택 로직 | 비전문가에게 우선/일반 물류로 설명. p3는 목적지 이름이지 3순위가 아님 |
| 목적지 포화 시 대기 구역 | p* 가득 차면 FRESH는 f*, NORMAL은 n*. Inventory는 실제 수량과 도착 예정 예약을 함께 capacity에서 차감 | 현재 코드 규칙으로 설명 가능. 실차에서 모든 경로 성공했다는 주장은 하지 않음 |
| 공간 생기면 대기 물류 즉시 재운송 | Docker가 완전히 빈 경우에만 대기 재고를 p*로 보충, FRESH 우선 | “입고 대기 물류와 우선순위 조건에 따라 다시 옮깁니다.” 공간만으로 즉시 실행된다고 하지 않음 |
| 팔레트 개별 ID 미관리 | Inventory README의 (zone_id, payload_type) 수량, 차량 적재 상태, transport operation ID | 본문은 종류·위치·작업 결과 관리만 설명. 물류 추적 자체가 필요 없다는 인상 금지 |
| SLAM이 현재 주행 위치 계산 | navigation-stack 선택 페이지: 지도 생성은 SLAM, 저장 지도 주행은 AMCL, Nav2가 주행 | “센서로 만든 지도와 현재 관측을 비교해 위치를 파악한다.” AMCL 이름은 본문 불필요 |
| Nav2, Auto Dock 역할 | vehicle API와 Orchestrator 정상 흐름에서 Nav2 접근/Auto Dock PICK/완료 보고 확인 | “목적지 접근”과 “팔레트를 집기 위한 마지막 정렬”로 설명 |
| YOLO + Depth 실제 Auto Dock 구현 | 새 사용자 원고에 명시. 이 작업 공간에 해당 구현 본체/통합 시험 증빙은 확인하지 못함 | 사용자에게 단계 질문. 미응답이면 일반적인 대상·거리 인식 역할로 본문을 제한하고 기술명 단정은 별도 메모 |
| Open-RMF 두 차량 관제·경로 배정 | 새 사용자 원고에 명시. 현재 서비스 문서는 Orchestrator가 WAIT 차량 배차/우선순위, Fleet Manager/Bridge가 명령 중계 | 사용자에게 단계 질문. 본문은 중앙 관제 역할로 설명하고 Open-RMF 자체가 모든 경로·재고·안전을 담당한다고 하지 않음 |
| 기존 산업 지게차 개조 완료 | 시연 대상은 MentorPi M1과 포크 구조물. 실제 산업 지게차 개조 증빙은 없음 | 현재 소형 실증, 기존 지게차 활용은 사업화 적용 방향. 적용 대상 장비의 제어/센서/현장 조건 검토 필요 |
| Gazebo로 실제 투입 전에 검증 | 사용자 제공 개발 과정 및 프로젝트 토픽·환경 문서 | 가상 환경 사전 검증으로 설명. 실차 처리량 예측 오차나 차량 대수 최적화 완료는 주장하지 않음 |
| 디지털 트윈으로 설치 전 처리량 보장 | 보정된 모델/실측 처리량 비교 증빙 없음 | 배치와 시나리오를 비교하는 사업화 방향. 예측값은 실측으로 확인해야 한다고 설명 |
| 정지·취소·재고 연계 | vehicle README와 P3 작업 흐름 | 완료 신호와 실제 상태 확인 후 낭독. 정지/취소는 별도 활성 주행에 각각 적용 |
| 안전 기능 | 소프트웨어 stop/cancel, OPERATOR_READY 후 다음 작업. 하드웨어 stop latch 부재 문서 명시 | 원격 정지/취소로 설명. 산업용 안전 인증이나 하드웨어 비상정지 동등성 주장 금지 |

## 사업 비교에 사용한 외부 1차 자료

- [BALYO 공식 홈페이지](https://www.balyo.com/): OEM 지게차 기반 자율 운반 장비와 MAP–SIMULATE–GO 단계 제시. 따라서 지게차 기반 자동화와 가상 사전 검증 자체는 경쟁사에 없는 독점 기능으로 주장할 수 없다. 이것만으로 ARANEUM 사업성이 없다고 결론 내리는 것도 부적절하다. 초기 고객, 해결 구간, 도입 공수·성과의 실증이 필요하다는 해석이다.
- [BALYO REACHY 공식 제품 설명](https://www.balyo.com/agv-reach-trucks/reachy): 산업용 지게차 기반, 수동/자동 이중 모드, WMS·ERP 연계 설명. AMR은 바닥 밑으로 들어가는 로봇 형태만 있는 것이 아니다.
- [Open-RMF 개요](https://openrmf.readthedocs.io/en/latest/): task queue, resource schedule, fleet adapter 등. 구체적인 배정 방식은 실제 fleet adapter/구현 범위에 따라 설명해야 한다.

외부 업체의 성능·절감액 수치를 ARANEUM의 효과로 차용하지 않는다. 경쟁 우위는 확정 사실이 아니라 검증할 사업 가설로 다룬다.
